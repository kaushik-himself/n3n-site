# AEO audit — November 3, 2026

## Result

The main site has basic crawlable HTML and metadata. Its AEO setup is not complete. Reading Room and the linked Substack homepage currently declare `noindex`; the desktop prototype's new content is still a draft and does not have published article routes.

This is an audit of a sample, not proof of indexing or visibility in an answer engine. No indexing, ranking, traffic, Core Web Vitals, or answer-citation score is claimed.

## Scope and method

Checked on November 3, 2026, America/Los_Angeles. Retrieved the public pages with Firecrawl using fresh full-page Markdown, raw HTML, and links. Corroborated crawl directives and status codes with independent HTTP GETs. Inspected the current Astro source and the desktop prototype. Evidence is in [the JSON snapshot](./aeo-2026-11-03-evidence.json).

Pages checked:

- https://n3n.lol/
- https://n3n.lol/writing/hello-world/
- https://n3n.lol/writing/ → https://nupoorneha.substack.com/
- https://reading.nehanupoor.com/ and its rendered Home view

Also checked the main site's robots.txt and common sitemap endpoints, Reading Room's robots.txt response, and the Substack homepage directly. Privacy, Terms, individual Substack posts, and the rest of the Reading Room were not audited page by page.

## Findings, in priority order

### 1. Reading Room declares an unintended indexing exclusion

**Observed:** https://reading.nehanupoor.com/ returns HTTP 200 with `<meta name="robots" content="noindex, nofollow">`. The same tag is in the initial HTML and rendered head. The initial body has an empty `div#root`; its content is rendered by JavaScript.

**Impact:** The `noindex` instruction excludes the page from normal search indexing. This is different from proving that a specific search engine has already removed it. Removing the tag creates eligibility; it does not guarantee indexing or citations.

**Decision and fix:** Neha confirmed that the exclusion is not intentional. The tag is removed in draft [Reading Room PR #25](https://github.com/neha-nupoor/reading-room/pull/25). This does not change the live deployment yet. No authentication or API access rules are weakened.

**Verify:** Inspect the deployed response head for both meta robots and `X-Robots-Tag`. Check URL Inspection after deployment. Keep private data and authenticated endpoints out of the crawl policy.

Reading Room's `/robots.txt` returns the app's HTML fallback with HTTP 200 and `text/html`, rather than a robots policy file. Serve a real text file when defining a crawler policy. That fallback is not evidence that all crawlers are blocked.

### 2. Writing leads to a Substack homepage marked noindex

**Observed:** https://n3n.lol/writing/ resolves to https://nupoorneha.substack.com/. The final page declares `<meta name="robots" content="noindex">`, confirmed by a direct request to Substack. The sampled page shows the publication description and a Coming soon post.

**Impact:** The homepage is currently declared non-indexable. This finding does not establish whether every individual post is excluded.

**Next action:** Inspect the publication's search/indexing settings and the canonical/robots directives of any substantive public posts. Keep the intended canonical owner clear if the same article is published on Substack and n3n.lol. No Substack settings were changed during this audit.

**Verify:** Retrieve the final page and selected public posts after any platform change. Check their robots directives and canonical URLs independently.

### 3. The desktop draft needs public routes before publication

**Observed:** The prototype is intentionally stored outside Astro's published tree. Its blog entries use hash links and fetch Markdown from GitHub after a click. Its app is loaded into an isolated iframe. The build tutorial is `draft: true`, so Astro does not publish its writing route. The current live homepage does not yet show the new Agents & Skills and tutorial content.

**Impact:** The visual prototype is not a substitute for published, discoverable pages. A crawler cannot be assumed to click a local app control and treat the fetched GitHub response as an article on n3n.lol.

**Next action:** Give Home, Agents & Skills, and each public article a stable URL and normal links. Return their readable content and metadata in the initial HTML, with the desktop interface as an enhancement. Build GitHub-authored Markdown into the published site. Keep draft content excluded until approved.

**Verify:** A direct request to each public URL should contain its title, body, canonical, and navigation without a click. Confirm reloads and browser history still work inside the desktop UI. Google can render JavaScript; this recommendation improves reliable access rather than claiming all JavaScript content is unindexable. See [Google's JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

### 4. Discovery and content are still limited

**Observed:** The live homepage and Hello World article return HTTP 200 with an H1, readable initial HTML, title, description, canonical, language, and ordinary links. No `noindex` meta or `X-Robots-Tag` was found on the sampled main homepage. The only sampled local article is a short introduction rather than substantive documentation of the site's work.

The main site's `/robots.txt`, `/sitemap.xml`, and `/sitemap-index.xml` return 404. No robots or sitemap source was found in the inspected Astro tree. This does not prove that a sitemap exists at no other URL, or that pages cannot be discovered through links.

**Next action:** Publish the approved bio, skill explanation, and agent build brief at real routes. Generate a sitemap of public canonical pages and reference it from a real robots.txt. Keep author identity and links consistent across the profile, skill, and article pages.

**Verify:** Check sitemap entries against the published routes and submit the sitemap through Search Console. A sitemap supports discovery but does not guarantee indexing. A missing robots.txt returning 404 is not, by itself, a crawl block. See [Google's sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview) and [robots response handling](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec).

### 5. Metadata improvements are pending, not an AEO shortcut

**Observed:** No JSON-LD or schema microdata was found on the sampled n3n homepage or Hello World article. The live head has basic Open Graph text but no share image. The draft PR already adds the coffee favicon and share image; those changes are not live yet.

**Opportunity:** Add accurate Person/WebSite and article structured data where it matches visible content. Publish the prepared share metadata. These improve description and sharing; missing special AI schema is not an indexing blocker.

Google states that its AI search features use the normal Search foundations and require no special AI text file or schema. See [AI features and your website](https://developers.google.com/search/docs/appearance/ai-features).

## Crawler policy and limits

OpenAI's search crawler is `OAI-SearchBot`. Its search policy is independent of `GPTBot`, which relates to model training. Search visibility does not require allowing training. When setting an explicit policy, use the [official crawler documentation](https://developers.openai.com/api/docs/bots) and check hosting rules as well as robots.txt.

This audit did not use Search Console, server crawl logs, verified crawler IP requests, or a paid visibility dataset. A successful Firecrawl request does not prove that every search crawler has access. Index status and AI-answer citations remain unverified.

The only crawl-rule edit authorized during the audit is the Reading Room meta-tag removal, after Neha confirmed that the exclusion was unintended. It is in a draft PR. Nothing was merged or deployed.
